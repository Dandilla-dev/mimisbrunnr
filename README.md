# Mímisbrunnr

Приложение, которое разбирает код репозитория и объясняет его простыми словами.
Рисует схему проекта, показывает каждую функцию вместе с её кодом, а пояснения пишет ИИ,
которого выбирает сам пользователь.

> Приветствую тебя. Wisdom awaits

## Что умеет (версия 0.5.4)

- **Загрузка кода:** публичный или приватный репозиторий GitHub (скачивается архивом, git не нужен)
  или папка на компьютере.
- **Разбор Python и JavaScript/TypeScript/JSX** — без ИИ, бесплатно и сразу:
  - функции, классы и методы;
  - React-компоненты и хуки, обработчики внутри компонентов;
  - редьюсеры из `createSlice`, маршруты Express;
  - граф «кто кого вызывает» и «какой компонент что рисует»;
  - тип переменной по результату функции: `session = memory.get(...)`, затем `session.add(...)` —
    связь с `Session.add` (из аннотации `-> Session`, из `return Session(...)`, из `list[Item]` в цикле);
  - методы родителя: `class Admin(User)` / `class Admin extends User`, вызов `admin.can_edit()` и
    `super().method()` ведут к методу в `User` с пометкой «унаследован»;
  - вызов через словарь или по строке — `handlers[kind](data)`, `getattr(obj, "export_" + fmt)()`:
    показываются все функции, которые могут сработать, с пометкой «одна из»;
  - если тип объекта нигде не записан, но метод с таким именем есть ровно у одного класса проекта, —
    связь с пометкой «предположительно» (слишком общие имена вроде `get`, `save`, `send` не угадываются);
  - функции, которые не вызываются, а передаются — в `onClick={handle}`, аргументом
    (`asyncio.to_thread(fn)`, `useSelector(selectX)`), в список: на схемах это пунктир с пометкой «передаётся».
- **Схема:** сначала файлы раскладываются по папкам, после объяснения ИИ — по смысловым слоям
  с обзором проекта.
- **С чего начать** — где программа начинает работать: `app.listen`, `uvicorn.run`, `FastAPI()`,
  `NestFactory.create`, `createRoot(...).render`, `if __name__ == "__main__"`, команды из `package.json`,
  `pyproject.toml`, `Procfile`, `Dockerfile`. Показано, как это найдено, и что делает файл запуска по порядку:
  подключаются модули → создаётся приложение → промежуточные обработчики → маршруты → запуск сервера.
  Если в проекте несколько программ (интерфейс и сервер), видны обе. Метка «▶ старт» — в обзоре,
  на частях проекта, файлах и схемах.
- **Схема взаимодействия, три уровня** (блоки и стрелки, масштаб колесом, сдвиг мышью,
  развёртывание на весь экран):
  - проект: части проекта и сколько вызовов идёт между ними; нажатие на стрелку показывает
    сами вызовы;
  - часть проекта: её файлы, связи между ними и с соседними частями. Стрелки к «общим» файлам,
    которыми пользуются почти все (например, `db.py`), по умолчанию скрыты — есть переключатель;
  - функция: кто её вызывает и кого вызывает она, на 1 или 2 шага;
  - **путь до функции**: выбираешь другую функцию — схема показывает, как одна доходит до другой по
    вызовам (все самые короткие пути), или говорит, что связи нет.
- **Как проходят запросы** (для веб-приложений) — все маршруты на одной схеме, по колонкам ролей
  слева направо: маршруты → проверки и обвязка → обработчики → логика → хранилище → данные.
  Блоки — функции или файлы (для большого проекта сразу файлы); можно оставить маршруты одного файла.
- **Диаграмма последовательности** для сценария: вверху участники (клиент, фреймворк, классы и файлы),
  вниз — шаги по порядку, ответ клиенту — обратной стрелкой. Переключается со списком шагов.
- **Чтобы схемы читались:**
  - наведение на блок выделяет его связи: синие — кто к нему обращается, бронзовые — к кому он;
  - под именем блока — фраза простыми словами (из пояснения ИИ, описания файла или docstring);
  - легенда под каждой схемой: виды стрелок, толщина — число вызовов;
  - «общие» функции, которые вызывают отовсюду (логгер, транзакция), не тянут к себе стрелки —
    их можно показать переключателем;
  - в большой схеме видны самые связанные блоки, остальное — в блоке «ещё N» (нажать — раскроется);
  - мини-карта в углу большой схемы: где ты сейчас, щелчок — перейти;
  - любую схему можно сохранить картинкой — PNG или SVG (кнопка ⤓).
- **Сущности (модели данных)** — Sequelize, Mongoose, TypeORM, Prisma, SQLAlchemy, SQLModel, Django,
  Pydantic, dataclass, DTO с class-validator:
  - поля с типами и правилами: ключ, обязательное, уникальное, по умолчанию, проверки;
  - таблица в базе и связи: «принадлежит», «имеет много», «многие-ко-многим через …»;
  - методы, которые добавляет связь (`book.setAuthors`, `author.getBooks`), и кто с сущностью работает
    (`Book.findByPk`, `prisma.note.create`, `this.repo.save`);
  - схема связей сущностей и пояснение ИИ: что хранит, что значат поля, пример записи.
- **Путь запроса** в веб-приложениях — Express, Fastify, NestJS, FastAPI, Flask:
  - от прихода запроса до ответа: `app.use(...)` по порядку, роутеры и префиксы, промежуточные
    обработчики, проверка доступа (JWT, guard'ы, `Depends(get_current_user)`, `login_required`),
    проверка данных (DTO, Pydantic-схемы, схемы Fastify, pipe'ы), обработчик, сервисы,
    репозитории, база данных;
  - чем отвечает (`res.status(201).json(...)`), какие ошибки бросает и куда они попадают:
    `next(err)` → обработчик ошибок → коды 404 / 409 / 500;
  - у каждого шага — роль, код и место, где он подключён.
- **Что внутри функции** — без ИИ, прямо из кода:
  - что приходит на вход: параметры, `req.params`, `req.body`, `process.env`, `request.json`;
  - каждая переменная: откуда берётся (`t ← await sequelize.transaction()`), где перезаписывается,
    куда уходит (в какой вызов, в ответ, в return, в проверку `if`);
  - чем заканчивается: return, ответ клиенту, throw, `next(err)`; транзакции, запросы в сеть, файлы;
  - по кнопке «Разобрать по шагам» ИИ делит код на смысловые куски и объясняет каждый; нажатие на шаг
    подсвечивает его строки. Сначала показывается оценка стоимости.
- **Сценарии** — путь выполнения шаг за шагом:
  - начала Mímisbrunnr находит сам: маршруты API, обработчики в интерфейсе (`handleSubmit`), main и
    корневые компоненты, тесты; начать можно и с любой функции;
  - шаги идут в том порядке, в каком вызовы стоят в коде, с условиями вокруг (`if …`, `else`,
    `for …`, `try`, `with …`, `.map(…)`); глубина 2–6;
  - у каждого шага — его код с отмеченными строками, откуда идут следующие шаги, и «где вызывается»;
    листать можно стрелками на клавиатуре;
  - по кнопке ИИ пишет связный рассказ: сводка и по фразе на каждый шаг. Сначала показывается
    оценка стоимости, действует лимит на запуск. Если код потом изменится, рассказ помечается.
- **Код целиком:** у каждой функции свой код и кнопка «Показать в файле», у файла — вкладка
  «Весь код». Подсветка синтаксиса, номера строк.
- **Разбор по шагам — для всех функций разом:** в обзоре кнопка «Разобрать по шагам все», в файле —
  «По шагам». Код каждой функции делится на куски, и каждый объясняется. Работает так же, как пояснения:
  оценка стоимости, лимит, остановка, пакетный режим за полцены; три функции идут одновременно.
  Совсем короткие функции (до 3 строк) по шагам не разбираются — им хватает обычного пояснения.
- **Встроенный справочник для начинающих** — короткие проверенные заметки о частых конструкциях:
  JavaScript и Python (async/await, try/catch, деструктуризация, декораторы, with…), Express, Sequelize,
  Mongoose, Prisma, NestJS, TypeORM, React и Redux, FastAPI, Pydantic, Flask, SQLAlchemy. У каждой
  функции — блок «Что здесь из языка и фреймворков» (работает без ИИ и интернета). Те же заметки
  получает модель, когда объясняет код, — поэтому одно и то же объясняется одинаково и без выдумок.
  Термины, которые уже есть в словаре проекта, модель второй раз не расшифровывает.
- **Пояснения ИИ по каждой функции:** что делает, вход и выход, связи, пример, на что обратить
  внимание. Плюс назначение каждого файла и словарь терминов.
- **Любая модель:** Anthropic (Claude) или любой OpenAI-совместимый API — OpenAI, Ollama,
  LM Studio и другие. Ключ шифруется средствами системы.
- **Деньги под контролем:**
  - оценка стоимости перед запуском;
  - лимит на запуск: дойдя до него, Mímisbrunnr останавливается, готовое сохраняется;
  - счётчик расходов за месяц;
  - **пакетный режим — вдвое дешевле** (Anthropic и OpenAI): все запросы уходят модели одним
    пакетом, ответ приходит обычно в течение часа (самое долгое — 24 часа). Пакет запоминается в
    разборе: приложение можно закрыть, результаты заберутся при следующем открытии. Пока пакет у
    модели, в шапке разбора видно, сколько готово; пакет можно отменить. Если за это время разбор
    переключили на другую ветку, пояснения сохранятся для той версии кода, которую отправляли.
- **Ветки:**
  - при загрузке по ссылке GitHub можно выбрать ветку (основная выбрана заранее);
  - в шапке разбора — переключатель веток: список берётся с GitHub, ветку можно сменить в любой момент;
  - пояснения хранятся для каждой версии функции: если в двух ветках функция одинаковая, пояснение
    одно; если разная — у каждой ветки своё, и при переключении туда и обратно ничего не теряется;
  - скачанные ветки сохраняются (до 8): повторное переключение не качает код заново, а без интернета
    открывается сохранённая копия;
  - для папки на компьютере видна текущая ветка git и список веток (читаются файлы `.git`, git не
    запускается); другую ветку можно открыть с GitHub, если у папки есть адрес `origin` на GitHub.
- **Обновление по кнопке «Обновить код»:**
  - изменённые функции помечаются «код изменился»;
  - новые — «нет пояснения»;
  - функция переименована или перенесена без изменений — пояснение переходит к ней само;
  - код новой функции очень похож на удалённую — «Похоже, переименована» с кнопкой «Перенести пояснение»
    (пояснение встаёт с пометкой «код изменился», чтобы сверить текст) или «Это другая функция»;
  - функции, которых нет в открытой ветке, но есть в другой скачанной, не считаются удалёнными: их
    пояснения сохранены и вернутся при переключении;
  - пояснения к действительно удалённым функциям — в «Требует внимания»: по одному или все разом;
  - переписываются только изменившиеся функции.
- **Разборы хранятся на компьютере** (SQLite) и открываются без интернета.

## Запуск готового приложения

**Linux:** скачайте `Mimisbrunnr-0.5.4.AppImage`, разрешите запуск и откройте:

```bash
chmod +x Mimisbrunnr-0.5.4.AppImage
./Mimisbrunnr-0.5.4.AppImage
```

Если AppImage ругается на FUSE: `sudo apt install libfuse2`
(или запустите с ключом `--appimage-extract-and-run`).

**Если окно стало чёрным или зависло:**
- Настройки → «Экран» → «Рисовать без видеокарты», затем перезапустить приложение. Помогает на
  Linux с Wayland (в том числе COSMIC) и с мониторами разного масштаба. Если видеопроцесс падает
  несколько раз, приложение само включит этот режим со следующего запуска.
- То же разово: `MIMIS_NO_GPU=1 ./Mimisbrunnr-0.5.4.AppImage`.
- Журнал ошибок: `~/.config/Mimisbrunnr/logs/mimisbrunnr.log` (путь есть в настройках). Упавшее окно
  приложение перезапускает само и записывает причину в журнал.

**Windows и macOS:** установщики собираются на серверах GitHub (см. «Сборка»). Приложение
не подписано, поэтому при первом запуске:
- **Windows** покажет предупреждение SmartScreen: «Подробнее» → «Выполнить в любом случае»;
- **macOS** скажет, что разработчик не подтверждён: «Системные настройки» → «Конфиденциальность
  и безопасность» → «Всё равно открыть».

## Подключение ИИ

Настройки → «ИИ для пояснений». Готовые варианты:

| Вариант | Что нужно |
|---|---|
| Claude Sonnet / Haiku | ключ API Anthropic (console.anthropic.com), баланс на счёте |
| OpenAI или совместимый | адрес API, ключ, название модели, цены |
| Ollama (бесплатно, без интернета) | установленная Ollama и скачанная модель: `ollama pull qwen2.5-coder:14b` |

Кнопка «Проверить подключение» отправляет модели короткий запрос.

Пакетный режим (вдвое дешевле, ответ позже) работает с Claude и с OpenAI (api.openai.com). У других
OpenAI-совместимых провайдеров его может не быть, локальным моделям он не нужен. Обзор проекта и слои
пишутся после пакета обычным запросом — им нужны назначения файлов из пакета.

Цены в готовых вариантах — на 18.11.2026; у провайдеров они меняются. Поставьте лимит
расходов ещё и в кабинете провайдера — это защита на случай любой ошибки.

Вы подключаете сторонний сервис: условия его использования, в том числе доступность в вашей
стране, соблюдаете вы. Код, который вы разбираете, отправляется выбранному провайдеру.

## Разработка

Нужен Node.js 22.

```bash
npm install
npm start          # собрать интерфейс и открыть окно
npm run dev        # режим разработки: интерфейс перезагружается при правках
npm test           # проверка ядра без сети и без настоящего ИИ
```

`npm test` ничего не скачивает и ничего не нужно настраивать: он разбирает маленькие учебные
проекты из `tests/fixtures/` — `py_app` (магазин на FastAPI + SQLAlchemy + Pydantic), `js_app`
(корзина на React + Express), `web_express` (Express + Sequelize), `web_nest` (NestJS + TypeORM),
`web_fastify` (Fastify + Prisma), `web_flask` (Flask) — и проверяет функции и связи, сущности, путь
запроса, «что внутри», оценку стоимости, лимит, обновление кода и хранение разборов. GitHub и модель при этом подделаны.

Для проверки интерфейса без трат есть поддельная модель: `node tests/fake-llm.mjs`. В настройках
выберите «OpenAI или другой совместимый API», адрес `http://127.0.0.1:8799/v1`, модель любая.

### Сборка установщиков

```bash
npm run dist:linux   # AppImage — можно собрать на Linux
npm run dist:win     # .exe — удобнее собирать на Windows
npm run dist:mac     # .dmg — только на macOS
```

Проще всего собрать все три автоматически: выложите проект на GitHub, откройте вкладку
Actions → Build → Run workflow. Готовые файлы появятся в разделе Artifacts
(`.github/workflows/build.yml`).

### Как устроено

```
electron/main.js       главный процесс: окно, меню, мост к ядру
electron/preload.cjs   безопасный мост: окну доступны только функции приложения
core/                  ядро без Electron (его проверяют тесты)
  fetchRepo.js         загрузка: GitHub zip или папка; код только читается, ничего не запускается
  parse/               разбор кода (tree-sitter, WebAssembly)
    python.js          функции, классы, методы, импорты, вызовы, Depends(...)
    js.js              функции, компоненты, хуки, классы, объекты, Express, импорты, JSX
  analyze.js           весь репозиторий → функции, граф, слои по папкам
  llm.js               вызов модели: Anthropic и OpenAI-совместимый формат; пакеты (Batch API)
  handbook.js          встроенный справочник: заметки и поиск их по коду
  explain.js           конвейер пояснений: план, оценка, пачки по файлам, лимит, обзор; пакетный режим
  scenario.js          сценарии: точки входа и цепочка шагов (общий для ядра и окна)
  story.js             рассказ сценария от ИИ: запрос, оценка, сохранение
  walk.js              разбор функции по шагам от ИИ
  parse/js_extras.js   сущности JS, веб-обвязка, поток данных внутри функций
  parse/js_web.js      путь запроса: Express, Fastify, NestJS
  parse/py_extras.js   сущности Python, FastAPI/Flask, поток данных
  parse/prisma.js      модели из schema.prisma
  store.js             настройки (settings.json) и разборы (*.mimis — база SQLite)
  core.js              всё вместе: этим пользуются окно и тесты
src/                   интерфейс: React + Redux Toolkit + Tailwind;
                       схемы — src/components/Graph.jsx (раскладка elkjs), src/features/session/Diagrams.jsx, Sequence.jsx
tests/                 core.test.mjs — проверка ядра; fake-llm.mjs — поддельная модель;
                       fixtures/ — учебные проекты на Python и JS, на которых идёт проверка
```

Где лежат данные пользователя:
- Linux: `~/.config/Mimisbrunnr/data`;
- Windows: `%APPDATA%\Mimisbrunnr\data`;
- macOS: `~/Library/Application Support/Mimisbrunnr/data`.

Точная папка показана в настройках. Разборы из первой версии (папка «Магистр») переносятся автоматически при первом запуске.

## Известные ограничения версии 0.3

- **Загрузка кода:** только GitHub и папки на диске. GitLab и другие хостинги — через папку.
- **Языки:** только Python и JS/TS. Go и другие — позже (tree-sitter их умеет).
- **Граф вызовов** строится по коду без запуска. Не видны вызовы, где имя функции целиком приходит
  из данных (`getattr(obj, name)()` без постоянной части имени, словарь, собранный в другом месте), и
  методы объектов, тип которых не записан, если метод с таким именем есть у нескольких классов.
- **Путь запроса** строится по коду, без запуска. Разбор понимает подключение в цикле по списку,
  записанному в коде (`for (const r of [a, b])`, `for m in (a, b)`), через функцию, которой передали
  приложение (`registerRoutes(app)`, `require('./routes')(app)`, `register_blueprints(app)`),
  условия (`if (dev) app.use(...)` — подписываются над шагом) и в NestJS — `APP_GUARD`
  и `consumer.apply().forRoutes()`. Если же что подключается, становится известно только при запуске
  (список из чужого пакета или настроек, автозагрузка файлов), маршрут помечается «путь неполный»
  с местом, где он, возможно, подключается. Django пока не поддерживается.
- **Сущности:** связи, заданные строкой из другого модуля или через миксины, могут не найтись.
- **Сценарии** идут внутри одного разбора: путь «кнопка во фронтенде → маршрут на бэкенде» виден,
  только если оба лежат в одном репозитории. Ветки `if/else` показаны обе — какая сработает,
  зависит от данных.
- **Разборы прошлых версий:** порядок вызовов и условия появятся после «Обновить код».
- **Не разбираются** папки `fixtures`, `__fixtures__` и `testdata` — там обычно учебные мини-проекты
  для тестов, а не код самого проекта.
- **Большие репозитории:** берётся не больше 4000 файлов, файлы больше 400 КБ пропускаются.
